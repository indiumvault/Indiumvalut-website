How to fix common JSON errors

JSON is a text format for representing structured data. A tiny punctuation mistake can make an otherwise sensible object invalid. Use these examples to find the usual problems, then validate your own sample.

1. Put double quotes around keys and strings

JSON requires double quotes around object keys and text values. Single quotes and unquoted keys are common mistakes.

Invalid JSON{ name: 'Mira', active: true }
Valid JSON{ "name": "Mira", "active": true }

2. Remove the trailing comma

Each item in an object or array is separated by a comma, but the final item must not have an extra comma after it.

Invalid JSON{ "project": "IndiumVault", "version": 1, }
Valid JSON{ "project": "IndiumVault", "version": 1 }

3. Match every brace and bracket

Objects use curly braces { }; arrays use square brackets [ ]. Every opening delimiter needs its matching closing delimiter in the right order.

{ "tools": [ "word counter", "JSON formatter" ] }

Here, the array closes first, then the outer object. If a parser reports an unexpected end, check for a missing closing brace or bracket near the bottom.

4. Use JSON's actual data types

  • Text: "hello" — use double quotes.
  • Number: 42 — no quotes needed for a numeric value.
  • Boolean: true or false — lowercase and unquoted.
  • Empty value: null — lowercase and unquoted.
  • List: ["red", "green"].
  • Object: {"enabled": true}.

JSON does not support comments, functions, or undefined values. If your data comes from JavaScript, convert it to strict JSON before validating it.

A simple debugging workflow

  1. Copy a sample of the JSON into the IndiumVault JSON formatter.
  2. Choose Format JSON to check whether the input parses.
  3. If it fails, read the error message and inspect the nearby quotes, commas, and brackets.
  4. Fix one issue at a time, then validate again.
  5. Before sharing data, remove passwords, API keys, personal details, and other secrets.

The formatter runs in your browser. Still, avoid pasting confidential or production data into any online tool unless you have reviewed and trust how it works.

Frequently asked questions

Does valid JSON have to be formatted across multiple lines?

No. JSON can be compact on one line or indented across several lines. Whitespace between tokens is generally optional.

Why does my JSON parser point to a character position?

The position is a clue, not always the exact location of the mistake. Check the character mentioned and the punctuation immediately before it.

Can JSON contain comments?

No. Standard JSON does not support line or block comments. Remove comments before validating strict JSON.
